# 图片生成与图库使用介绍

> 全场景图片能力：书籍封面、角色定妆照、正文插图、分镜图。核心是**两段式生图**——中文场景描述先由对话模型转写成专业英文 prompt，再交生图模型出图——并支持 1–4 张候选挑选、本地上传与图库复用。

---

## 一、进入方式（生图入口）

| 入口 | 用途 |
|---|---|
| 编辑器工具栏「插图」 | 先选中一段场景文字，AI 生成插图插入光标处 |
| 书架书卡 hover「封面」 | 设置书籍封面 |
| 角色卡「设置图片」 | 生成 / 上传角色头像与立绘（按已填字段自动组场景） |
| 剧本分镜画板 | 逐镜 AI 分镜图（2 候选）或批量补图，见 [剧本工作台说明](./剧本工作台说明.md) |
| 世界地图「AI 生成底图」 | 直接生成地图底图，不经过图库，见 [世界地图说明](./世界地图说明.md) |

封面 / 角色 / 插图三处共用统一选择器，三个来源任选：**本地上传**（不依赖 AI 配置）、**AI 生成**、**从图库选**。

## 二、两段式生图流程

1. **场景描述（中文）**：按入口自动预填（封面按书名与题材、角色按角色卡字段、插图按选中场景），可改写；另有"补充要求（可选）"填风格 / 构图 / 光影。
2. **提示词转写**：对话模型把中文描述转写为专业英文 prompt + 负面词（走「图片提示词转写」功能点，可用便宜模型）。转写失败会降级直接用中文描述生成。
3. **生图**：生图模型出图（走「图片生成」功能点）。

生成设置：

| 项 | 说明 |
|---|---|
| 尺寸 | 512×512 / 768×768 / **1024×1024（默认）** / 1024×1536 / 1536×1024 |
| 候选数 | 1–4 张，默认 2；**仅勾选的图片会入库**，未选中的关闭即丢弃 |
| 高级模式 | 勾选后跳过转写，手写英文 prompt 与负面词直接生图；绑定 ComfyUI 且有自定义工作流时可在此切换"默认 / 自定义" |

## 三、图库管理

编辑器右栏「资产 → 图库」：

- **用途筛选**：全部 / 封面 / 角色 / 插图。
- **上传**：「+ 上传」支持 png / jpg / webp / gif / bmp；在正文中**粘贴或拖入图片**也会自动入库并插入插图节点。
- **复用**：缩略图 hover「插入」按钮，把图片插入正文光标处（可重复使用）。
- **删除保护**：删除前做引用检查（书籍封面 / 角色关联 / 章节正文三类），有引用时列出全部引用位置，强制删除后相应位置显示占位并同步清理正文引用。
- **角色图规则**：同一角色至多关联一张；更换后旧图自动转回图库；"清除图片"只解除关联，文件保留。

## 四、ComfyUI 本地生图

设置页「模型接入 → ComfyUI（本地生图）」预设卡（默认 `http://127.0.0.1:8188`，免 API Key，需本地服务运行中）：

- 「模型」填 Checkpoint 文件名（可选，留空用工作流默认）。
- **自定义工作流**：编辑配置时「导入工作流 JSON」——必须是 ComfyUI「导出（API 格式）」的节点对象 JSON；参数按**节点类型**注入（KSampler 写提示词与 seed、EmptyLatentImage 写尺寸、CheckpointLoader 写模型），兼容用户自己的工作流；「清除」恢复内置默认 txt2img 工作流。

## 五、模型接入要点

| 功能点 | 说明 |
|---|---|
| 图片生成 | 需绑定 OpenAI 兼容平台（OpenAI / 硅基流动 / 火山方舟等）或 ComfyUI；**Google、Anthropic 协议不支持生图** |
| 图片提示词转写 | 普通对话模型即可，建议绑便宜配置 |

未配置时的报错会直接给出指引（先加 Provider，再到「模型分工」绑定对应功能点）。详见 [模型接入说明](./模型接入说明.md)。

## 六、存储与备份

- 图片文件存于本书目录 `assets/` 下，图库只存元数据；随书备份（手动与自动）都会打包全部图片。
- 导出联动：EPUB / DOCX / Markdown 导出默认内嵌封面与插图（Markdown 把图片复制到输出目录 `images/`），TXT 忽略图片；文件缺失时降级占位不中断。
- 用量统计不覆盖图片生成与向量嵌入的消耗。

## 七、限制与提示

- 正文中的插图节点支持点击编辑图注、宽度（25% / 50% / 100%）与对齐，可拖动。
- 分镜图固定 1536×1024、2 候选，单选一张入库；地图底图独立于图库。
- 生图服务端不支持一次多张时，应用会自动改为逐张请求补齐候选数。
